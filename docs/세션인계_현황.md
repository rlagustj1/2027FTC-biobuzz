## 🔴 지금 막혀있던 지점 (다음 세션이 이어받을 곳)

`DashboardDriveOpMode`에서 **위치+회전을 함께** 제어하려는 중.

### 시도한 접근
1. 위치+회전 **동시 제어** → 나선형으로 발산 (로컬프레임 변환이 회전중 heading을 계속 참조해서 꼬임)
2. **2단계(TURN→MOVE) 순차 제어**로 변경 — 회전 먼저 끝내고 위치 이동
   - TURN 단계에서 heading이 허용오차 안에 "순간적으로만" 스쳐도 바로 MOVE로 전환돼버려서
     불안정한 상태로 이동 시작 → 정착시간(SETTLE_MS=300ms) 도입해서 일정 시간 계속 안정적이어야
     전환되게 수정
3. 그런데 **목표 heading이 현재 heading과 거의 정반대(180도 근처)인 경우**, dirLock 버그로 인해
   phase가 계속 "TURN"에 머물면서 로봇이 오른쪽으로 미세하게 떨기만 하고 진전이 없는 증상 확인
   → dirLock 버그 수정(위 5번 항목) 적용해서 배포까지 함
4. **직후 재검증 결과 (세션 종료 직전 마지막 스크린샷)**:
   - 목표: X=0, Y=-0.4, heading=0
   - 결과: X=-0.648, Y=0.544, heading=-176.0 (전혀 도달 못 함, 이상한 궤적)
   - 즉 dirLock 버그를 고쳤는데도 **여전히 heading이 -176도에서 거의 안 움직이고**, 위치도 엉뚱한
     곳으로 감. **원인 미해결 상태로 세션 종료.**

### 다음 세션이 확인할 것 (우선순위 순)
1. **왜 heading이 -176도에서 안 움직이는지** — dirLock 버그를 고쳤는데도 안 되면:
   - `MIN_TURN_POWER`나 `KP_HEADING` 자체가 이 각도 근처에서 부호 계산이 잘못됐는지 코드 재검토
   - 혹은 로봇이 실제로 그 방향으로 최소출력을 받고 있는데 **메카넘 마찰 때문에 안 돌고 있는 것**인지
     (TurnTest 단독으로는 90도 회전이 잘 됐으므로, 이 각도 근처에서만 문제일 수도 있음 — 정말 180도
     근처인지, 아니면 DashboardDriveOpMode 특유의 다른 변수가 있는지 확인 필요)
   - DS 폰 텔레메트리에서 `phase`, `w 출력`, `오차(°)` 실시간 값을 직접 보면서 라이브 디버깅 권장
     (스크린샷/사후 분석보다 훨씬 빠름)
2. 원인 파악되면 수정 → 재배포 → 재검증
3. **된다면**: 대시보드 완전판(위치+회전) 완성, 커밋
4. **시간 없으면**: `DashboardDriveOpMode`를 위치제어만(회전 부분 주석처리/제거)으로 되돌리는 것도
   합리적 선택지. 이미 검증된 상태로 안전하게 마무리 가능. (사용자가 "오늘 다 끝내야 함"이라고
   했었으나, 세션이 끊기게 되어 다음 세션 판단에 맡김)

## 배포 방법 (USB, 매번 이렇게 함)

```powershell
# 1. adb 경로 (PATH에 없으면)
$ADB = "C:\Users\hyeon\AppData\Local\Android\Sdk\platform-tools\adb.exe"

# 2. 기기 확인
& $ADB devices

# 3. 빌드+설치 (JAVA_HOME 필요, Android Studio 번들 JDK 사용)
$env:JAVA_HOME = "C:\Program Files\Android\Android Studio\jbr"
cd C:\Users\hyeon\AndroidStudioProjects\2027FTCbiobuzzseason
.\gradlew.bat :TeamCode:installDebug

# 4. RC 앱 실행 (재설치 후 자동 실행 안 될 때가 많음)
& $ADB shell am start -n com.qualcomm.ftcrobotcontroller/org.firstinspires.ftc.robotcontroller.internal.FtcRobotControllerActivity

# 5. 필요시 시계 설정 (재부팅 후 1970년이면)
& $ADB shell "date MMDDhhmmYYYY.ss"   # 예: date 070720002026.00 = 7/7 20:00 2026

# 6. 대시보드용 포트포워딩 (USB로 대시보드 테스트할 때)
& $ADB forward tcp:9999 tcp:9999
```

**중요**: USB 케이블이 자주 끊긴다 (adb reconnect 필요). 매번 `& $ADB devices`로 확인 후 진행.
재설치(uninstall 후 install) 시 **권한(위치/카메라/저장소)이 리셋**되므로 다시 grant 필요할 수 있음:
```powershell
& $ADB shell pm grant com.qualcomm.ftcrobotcontroller android.permission.ACCESS_FINE_LOCATION
# (CAMERA, READ_EXTERNAL_STORAGE, READ_PHONE_STATE, WRITE_EXTERNAL_STORAGE 등도 동일)
```

## 대시보드 실행법

자세한 내용: [docs/대시보드_실행법.md](대시보드_실행법.md)

핵심: 로봇에서 `Dashboard Drive` OpMode START → PC에서
```
python pc/dashboard.py --robot-host 127.0.0.1 --robot-port 9999   # USB(adb forward) 경유
python pc/dashboard.py --robot-host 192.168.43.1 --robot-port 9999 # WiFi 직접 (노트북 인터넷 끊김 주의)
```

**주의**: RobotCommServer는 1클라이언트만 지원. 진단용으로 Claude가 소켓에 테스트 접속하면
대시보드 연결이 끊긴다 — 동시에 여러 곳에서 접속 시도하지 말 것.
